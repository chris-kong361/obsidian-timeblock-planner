# 时间块规划师 (Timeblock Planner)

> **English** · A time-blocking & goal-tracking plugin for Obsidian. Plan your day on a visual timeline (day view & week view): drag to create, move and resize time blocks; blocks are saved as plain Markdown in daily notes. Break goals down into small steps, tick them off, and turn any step into a scheduled time block in one click. Track goals by invested hours — goal progress is computed automatically from completed time blocks, with weekly/today stats. No network calls by default; optional private-Gist sync keeps desktop and mobile devices in sync. Works on desktop and mobile.

Obsidian 插件：目标管理 + 时间块（Time Blocking）日程规划。

## 功能

- **日视图 / 周视图**：顶栏「日 / 周」一键切换
  - 日视图：单日大时间轴，块可拖拽移动、底部拉伸调时长
  - 周视图：7 列并排（周一～周日），今日列高亮 + 红色时刻线，列内空白处拖拽即可创建时间块，点击列头跳到该日
  - 两个视图都支持 0:00–24:00 全天时间轴（可在设置中调整）、30 分钟网格对齐
- **拖拽创建时间块**：在时间轴空白处按住拖拽选一个时间段，松手后填写内容
- **点击完成**：时间块右上角圆圈一键打卡，右键弹出菜单（完成/编辑/删除）
- **目标管理**：目标库面板，每个目标设定「目标投入时长（小时）」，进度条按已完成时间块的时长自动累计（累计 / 本周 / 今日）
- **目标拆解**：把目标拆成一个个小步骤，勾选推进；
  - 编辑目标时添加步骤（回车加下一步、可粘贴多行、可排序）
  - 目标卡展示 `2/5 步` 进度和「下一步」，展开可逐条勾选
  - 步骤右侧「＋」直接为这一步安排时间块，块标题自动填入步骤内容
- **一键安排时间**：在目标卡上点「安排时间」，新建时间块自动关联该目标
- **数据全部是 Markdown**：
  - 日程：`时间块规划/日程/YYYY-MM-DD.md` 的 `## 时间块` 区段
  - 目标：`时间块规划/目标库.md` 的表格 + `## 目标拆解` 区段
  - 可手动编辑、可被同步工具 / 其他插件读取
- **双端同步（可选）**：内置 GitHub Gist 云同步，手机与电脑不必是同一个库也能自动同步；见下方「双端同步配置」
- **外部修改自动刷新**：手机端或其他编辑器改动后视图自动重载；补齐 `create` / `rename` 事件，并有内容哈希轮询兜底
- **手机 / 平板可用**：轻点空白处新建、点时间块编辑、块上拖动改时间、目标库抽屉、周视图横向滚动；电脑端保留原有拖拽圈选与 hover 交互
- 支持日期切换（查看过去 / 未来日程）

## 时间块格式

```markdown
## 时间块
- [ ] 09:00 - 10:30 | 写周报 | 分类:专注 | 目标:求职准备 | 备注:先列大纲
- [x] 11:00 - 11:30 | 复盘昨日
```

## 目标库格式

```markdown
| 目标 | 目标时长(h) | 截止日期 | 状态 |
| --- | --- | --- | --- |
| 找到用户运营工作 | 60 | 2026-12-31 | 进行中 |

## 目标拆解

### 找到用户运营工作
- [x] 整理 10 份 JD，提炼关键词
- [ ] 改简历初稿
- [ ] 找 3 位学长做模拟面试
```

## 安装

**官方目录（电脑 / 手机相同）**：设置 → 第三方插件 → 浏览 → 搜 `Timeblock`（显示名是英文）→ 安装并启用。条目已标记为 Desktop, Mobile，两端都能装。

**如果点安装一直转圈 / 报网络错误**（国内网络访问 GitHub Release 常见失败），改用手动安装：

1. 从 [Releases](https://github.com/chris-kong361/obsidian-timeblock-planner/releases) 下载 `main.js`、`manifest.json`、`styles.css` 三个文件；打不开 GitHub 时可用 GitHub 镜像加速下载。
2. 放进**当前仓库**的 `.obsidian/plugins/timeblock-planner/` 目录。手机端可用系统文件 App / 同步工具复制，路径与电脑端一致。
3. 设置 → 第三方插件 → 刷新列表 → 启用。

手机端在目录里搜不到时：确认搜的是英文 `Timeblock`、关掉「仅显示已安装」、完全退出并重启 App 让它重新拉取目录。

## 双端同步配置

插件默认只读写**本机库**里的 Markdown，两端若是不同的库，计划不会互通。开启内置同步后，数据通过**你自己的私有 Gist** 在两端之间传递，不经过任何第三方服务，也不要求两端用同一个 vault 或同一套同步服务。

### 第一步：创建 GitHub Token（只做一次，两端共用同一个）

Token 相当于插件专用的钥匙，**只授予 Gist 读写权限**，不碰你的仓库代码。用你自己的 GitHub 账号在网页上建，插件无法代劳。

**方式 A：classic token（最简单，推荐）**

1. 登录 GitHub → 右上角头像 → **Settings**
2. 左侧最底部 **Developer settings** → **Personal access tokens** → **Tokens (classic)**
   （若默认显示的是 Fine-grained tokens，点左侧的 *Tokens (classic)* 切换）
3. **Generate new token (classic)** → 可能需要输入密码 / 二次验证
4. **Note** 填 `timeblock-sync`；**Expiration** 建议选 `No expiration`（选 90 天也行，但到期后要换新 Token 并在两端重填）
5. 权限**只勾 `gist` 这一项**，其余全部不勾
6. 拉到底 **Generate token** → 复制 `ghp_…` 开头那串字符 → **立刻存好**（离开页面后不再显示）

**方式 B：fine-grained token（可选）**

- Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
- Resource owner 选自己的账号；Repository access 选 `All repositories` 即可（不必授予任何仓库权限）
- 在 **Account permissions** 里把 **Gists** 设为 **Read and write**
- 生成后复制 `github_pat_…` 开头的字符串

> Gists API 的创建 / 更新需要 **Gists 写权限**；只给只读会导致「创建新的同步 Gist」或「立即同步」失败。

### 第二步：电脑端建 Gist 并上传

1. Obsidian → **设置 → 第三方插件 → Timeblock Planner（时间块规划师）**，滚到 **「双端同步（GitHub Gist）」**
2. 把 Token 粘进 **GitHub Token**（输入框是密码框，显示为圆点，正常）
3. 点 **「创建新的同步 Gist」→ 创建**：插件自动建一个 **Secret（私有）Gist**，把 32 位的 **Gist ID** 自动填进上面的输入框，并自动打开「启用双端同步」
   - 不用去 gist.github.com 手动建；若手动建了，把网址末尾那串 ID 填进 **Gist ID** 也可以
4. 确认 **「启用双端同步」**、**「自动同步」** 都开着
5. 点 **「上传覆盖云端」**（提示「已用本地数据覆盖云端」），再点一次 **「立即同步」**
   - 这一步把电脑上已有的计划作为基准写进云端，避免手机端空数据反过来把电脑数据冲掉

### 第三步：手机端接入（关键：同一份 Token + 同一个 Gist ID）

1. 把 Token 和 Gist ID 发到手机（微信文件传输助手 / 备忘录均可；插件会自动去掉首尾空格）
2. 手机端 Obsidian → 设置 → 第三方插件 → Timeblock Planner → 「双端同步」
3. 粘贴**同一个 Token**、**同一个 Gist ID**；**不要点「创建新的同步 Gist」**，否则会另建一个空 Gist，两端就对不上了
4. 打开 **「启用双端同步」** 与 **「自动同步」**
5. 点 **「从云端恢复」** 把电脑端数据拉到手机，再点 **「立即同步」**

### 第四步：验证双向

- 电脑端在某天新建一个时间块 → 等 3～5 秒 → 手机端点 **「立即同步」**（或切后台再回前台）→ 切到同一天应能看到
- 反过来手机端勾掉一个任务 → 电脑端点 **「立即同步」** → 也应同步
- 设置页顶部实时显示同步状态；命令面板搜 **「立即同步（双端）」** 可随时手动触发

**首次两端已有不同数据时**：先各自把 `时间块规划/日程` 文件夹复制一份备份；在数据最全的一端点「上传覆盖云端」，另一端点「从云端恢复」。之后日常编辑交给按天合并，不同日期的改动互不覆盖。

**同步规则**

- 按「天」+「目标库」两个粒度合并：两端改不同日期互不干扰；只有一端改过就取改过的那端
- 同一天两端都改：保留最后保存的版本，并弹出提示告知
- 云端数据写回本地时只重写 `## 时间块` 区段 / 目标表格与 `## 目标拆解`，**保留笔记里手写的内容**
- 触发时机：编辑后 3 秒防抖推送、每 60 秒拉取、App 回前台拉取、手动「立即同步」
- 数据始终以 Markdown 存在库里；关掉同步或删掉 Token，插件行为与旧版完全一致

**常见报错排查**

- `401` — Token 复制不全、已过期或已撤销 → 重新生成并在两端重填
- `403` / `404` — 权限不足（classic 没勾 `gist`，或 fine-grained 的 Gists 没给 write）、Gist ID 填错、两端填的不是同一个 ID
- 一直转圈 / 超时 — 设备需能访问 `api.github.com`；国内网络不稳定时先确认 GitHub 能否打开。同步失败不影响本地使用，数据仍在本机 Markdown 里
- 手机端误点了「创建」 — 两端 ID 不一致，把电脑端的 Gist ID 复制过去覆盖手机端的，再「从云端恢复」
- Token 到期 — 生成新 Token 后**两端都要重新粘贴**

**注意**

- Token 明文保存在本机 `.obsidian/plugins/timeblock-planner/data.json`。若你的库用 OneDrive / Obsidian Sync 同步了 `.obsidian` 目录，Token 会跟着同步；介意的话请自行斟酌
- Gist 是私有的，但别把 Token 发给别人；不用了到 GitHub 撤销该 Token
- 两端若本来就是同一个同步中的 vault，也可以不启用云同步 —— 本地文件变更检测（`create` / `rename` + 内容哈希轮询）已加固
